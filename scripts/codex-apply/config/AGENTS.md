# Global Working Guidelines

## Communication
- 原則として日本語で説明する。
- コード、コマンド、ファイル名、識別子は必要に応じて原文のまま扱う。
- 確認できた事実、推測、未検証事項を区別する。

## Before Work
- 作業開始時に現在のディレクトリと関連ファイルを確認する。
- 既存の実装、テスト、README、プロジェクト固有のAGENTS.mdを優先して把握する。
- 影響範囲が広い変更や要件が曖昧な変更では、実装前に短い計画を示す。
- 明確な依頼がない限り、無関係なファイルを変更しない。

## Implementation
- 既存の設計・命名・スタイルに合わせ、必要最小限の差分を優先する。
- 既存の変更を勝手に破棄しない。
- 破壊的な操作、依存関係の大幅更新、外部送信は目的と影響を確認してから行う。
- 秘密情報をコード、ログ、回答に不用意に含めない。

## Verification
- 変更した場合、関連するテスト・静的解析・差分確認を可能な範囲で実施する。
- テストを実行できない場合は、理由と未検証の範囲を明記する。
- 成功していない検証を「成功」と報告しない。

## Review and Test Design
- レビューでは根拠となるファイルと該当箇所を示し、重大度順に指摘する。
- テストケース設計では正常系、異常系、境界値、状態遷移を必要に応じて検討する。
- 仕様にない期待結果を断定せず、確認が必要な項目として区別する。
- テストケースの列構成・粒度・ID採番は案件固有のルールに従う。

## Final Report
- 実施内容、変更ファイル、検証結果、残課題を簡潔にまとめる。
- 読み取り専用の依頼では、ファイルを変更しない。

# 共通の作業方針

- 原則として日本語で説明する。コードや識別子は必要に応じて原文を使う。
- 作業前にプロジェクトの README と AGENTS.md を確認する。
- 既存の変更を保持し、依頼に必要な範囲だけを変更する。
- 変更後は関連する検証を行い、確認した事実と未検証事項を区別する。
- 秘密情報や認証情報をコード、ログ、回答へ出力しない。
